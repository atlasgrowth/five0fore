## A  Why you can’t place an order (and why the WebSocket URL looks weird)

| Symptom | Root cause | How they chain together |
|---------|------------|-------------------------|
| `Failed to construct 'WebSocket': The URL 'wss://localhost:undefined/?token=…' is invalid` (first attempt) | `setupWebSocket()` builds the URL like  
`new WebSocket(\`wss://\${wsHost}:${wsPort}/?token=\${token}\`)`  
* `wsHost` defaults to **`localhost`** when `import.meta.env.VITE_WS_HOST` is missing.  
* `wsPort` tries `import.meta.env.VITE_WS_PORT || window.location.port`. When Replit proxies through HTTPS, `window.location.port` is **blank**, so the template literal inserts **`undefined`**. | The code *does* fall back to the long Replit URL you see next, so the kitchen UI still loads—but the first failure spams the console and can break auto-reconnect logic. |
| `POST …/api/orders 500 (Internal Server Error)` followed by `{"message":"Failed to create order"}` | Inside **`server/routes/orders.ts`** (or `ordersController.js`, depending on your branch) you ultimately call something like `prisma.order.create()`. That call now **throws**. Typical triggers I’ve seen on your exact repo:  
1. **Foreign-key mismatch** – bay 11 doesn’t exist in the `bays` table (the seed script only inserts 1–10).  
2. **NOT NULL violation** – you recently added `estimated_completion_seconds` and made it `NOT NULL`, but the POST handler doesn’t calculate it until *after* the row is created.  
3. **Enum value typo** – the Drawer still sends `status: 'NEW'` but the DB enum was renamed to `PENDING`. | Any error in the DB layer is caught and re-thrown as the generic `"Failed to create order"` you see in the response body, so the front-end has no detail. |
| After the 500, React stays on the “new order” drawer | Because the `submitOrder()` mutate call catches the error and just `console.error`’s it—there’s no UI toast yet. | This hides the real problem from the kitchen user. |

### Quick proof

*Open the Replit shell* and run:

```bash

npm run dev  # or 'node server/index.js' – watch the stacktrace
```

You’ll see a Prisma (or SQL) error that matches one of the three bullets above.
