### Why “Served → Closed” is still broken after the last patch

| Layer | What the Replit agent added | Hidden mismatch that breaks it |
|-------|----------------------------|--------------------------------|
| **Database** | Added `closed_at` column and sets `status = "CLOSED"` | Enum in `shared/schema.ts` is `OrderStatus.SERVED`, `OrderStatus.CANCELLED` – **no `CLOSED` value**, so Drizzle casts it to `unknown`; filters can’t match. |
| **API filter** `/api/orders?status=CLOSED` | Reuses switch-map that lower-cases the param and compares to enum | Because enum lacks `CLOSED`, the map falls into *“invalid status”* → 400 or returns nothing. |
| **Client query** | Closed tab calls `useQuery(['orders','closed'], …fetch('/api/orders?status=CLOSED')…)` | Fetch returns 400/empty array → badge never updates. |
| **WebSocket** | Broadcasts `{ type:'ORDER_CLOSED' }` | Client switches only on `'ordersUpdate'` / `'order_updated'`. The new message is ignored. |

So the UI looks like “button did nothing” even though DB row changed.

---

## Two-step fix (no column renames, minimal disruption)

### Step 1 — Use existing enum value `SERVED` instead of inventing `CLOSED`

* Replace every place we set `"CLOSED"` with `"SERVED"` and use `servedAt` timestamp (you already have it).
* Remove `/close` endpoint; just have the “$” button call `/order/:id/serve` (it already exists and changes status).
* Closed tab should filter `status=SERVED`.

### Step 2 — Client cache + badge refresh

* After `$` click invalidate both `['orders','served']` and `['orders','all']`.
* Closed tab query key should be `['orders','served']` not `['orders','closed']`.
